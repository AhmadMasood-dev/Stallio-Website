# Spanish i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add English ↔ Spanish locale routing and translations across all completed Stallio marketing and auth pages using `next-intl`.

**Architecture:** Prefixed routes under `src/app/[locale]/...`, message catalogs in `messages/{en,es}.json`, `proxy.ts` for locale negotiation, `Link`/`useRouter` from `@/i18n/navigation`, header language switcher.

**Tech Stack:** Next.js 16.3 App Router, React 19, `next-intl`, TypeScript, existing Tailwind/shadcn UI.

**Spec:** `docs/superpowers/specs/2026-08-22-spanish-i18n-design.md`

## Global Constraints

- Locales: `en`, `es` only; `localePrefix: 'always'`
- No emdashes/en-dashes in user-facing copy
- Preserve existing component structure and visual design
- Verify with `npm run lint` and `npm run build`
- Do not add Co-authored-by trailers to commits

## File map

| Path | Responsibility |
|------|----------------|
| `src/i18n/routing.ts` | Locale list + `defineRouting` |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `redirect`, `usePathname`, `useRouter` |
| `src/i18n/request.ts` | Load messages per locale |
| `src/proxy.ts` | next-intl locale proxy (Next 16) |
| `messages/en.json` / `messages/es.json` | Translation catalogs |
| `src/app/[locale]/layout.tsx` | Locale html lang + provider |
| `src/app/[locale]/**` | Moved pages/layouts |
| `src/components/layout/LanguageSwitcher.tsx` | EN \| ES control |
| Section/auth/layout components | Consume `t()` instead of hardcoded English |
